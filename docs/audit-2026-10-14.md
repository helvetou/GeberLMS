## 5. Functional scenarios (§6) — status

### ⛔ Execution blockage (exact reason)

The dev server **does not start without Cloudflare credentials**, which are not listed
in the manual's prerequisites (§1):

- `npm run dev` (Vite): adapter-cloudflare emulates the platform via `getPlatformProxy`
  → failure "`Failed to start the remote proxy session … CLOUDFLARE_API_TOKEN`".
  Observed: `GET /login` → **HTTP 500**.
- `wrangler dev`: `DB`/`FILES`/`ASSETS` bindings in `local` mode, but the **`AI` binding is `remote`**
  → same error, the Worker does not start.

Consequently, §6 scenarios were verified by **static inspection of the wiring**
(actions, role guards, services) — all present and coherent — but **not validated live in a browser**.

## 7. Non-conformities (FAIL) and anomalies

### 7.1 — ❌ §3: non-reproducible startup instruction (MAJOR)
`npm run dev` requires `CLOUDFLARE_API_TOKEN` (or interactive `wrangler login`), **not listed
in prerequisites §1**. On a fresh clone, the login page returns HTTP 500/503.
→ *Action: document the prerequisite and specify that local dev goes through the Cloudflare
platform (remote `AI` binding).*

### 7.2 — ❌ §6.5: coupon enable/disable not implemented
The manual claims to "enable/disable" coupons. The `admin/coupons` route only exposes `create`;
no toggle action/service. The `enabled` field exists but is only read (display "disabled") and forced `true` at creation.
→ *Action: implement the toggle, or remove the claim from the manual.*

### 7.3 — ⚠️ §2: non-idempotent migrations (MINOR)
Re-running migrations on an already-migrated DB fails: `table already exists` /
`duplicate column name`.

### 7.4 — ⚠️ §2: `seed-admin.ts` non-idempotent (MINOR)
Fails with `UNIQUE constraint failed: users.email` if the admin already exists (unlike
`seed-demo.ts`, which deletes then re-inserts).

### 7.5 — ⚠️ §6.9/§7: ambiguous initial progress state (MINOR)
`seed-demo.ts` inserts `progress.status='completed'`: the demo lesson is **already done**
on first display, weakening the "mark complete" demonstration.

## 9. Recommendations

1. **Manual §1/§3**: add the `CLOUDFLARE_API_TOKEN` prerequisite (or `wrangler login`) and
   specify the Cloudflare platform dependency for local dev.
2. **§6.5**: implement the coupon enable/disable toggle, or fix the manual.
3. Make migrations and `seed-admin.ts` **idempotent** (or document the fresh-DB requirement).
4. Replay the full browser audit in an environment with Cloudflare credentials.
5. Trivial: remove the `completed` insert from the demo seed, or document the initial state.
