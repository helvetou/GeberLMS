# Course plan — IoT & Connectivity

> Forecasted course for the **GeberLMS / LMS Helveticore** catalogue.
> Status: **planning (incremental build)**.
> Complements: `embedded-systems/` (the device stack) and
> `embedded-software-design/` (the design methodology). This one is the
> **wireless + edge + cloud** layer.

---

## 1. Why this course

The embedded/IoT survey shows connectivity skills are the "phased out" axis:
the data has **zigbee (2), BLE (2), MQTT (1), OPC-UA (1), edge (15)** in
postings, and the *modern* standards — **Matter/Thread, LoRaWAN, NB-IoT/LTE-M,
Zephyr-based connectivity** — barely appear because the current sources skew to
automotive/enterprise. This course covers the full IoT stack so the profile
stops being hardware-only and becomes *device → edge → cloud*.

## 2. Learning outcomes

1. Select the right radio per use case: **BLE, Zigbee/Thread/Matter, LoRaWAN,
   NB-IoT/LTE-M**.
2. Implement a **BLE peripheral** (GATT) and a **Matter/Thread** endpoint.
3. Publish device data over **MQTT/CoAP** to a broker and a cloud IoT hub.
4. Build a **battery/lower-power** sensor node (sleep modes, duty cycle).
5. Apply **edge computing** and **sensor fusion** on constrained devices.
6. Integrate **IIoT** (Modbus, OPC-UA, PLC/SCADA) and an **OTA** update loop.
7. Harden the device: **secure boot, provisioning, TLS**.

## 3. Audience & prerequisites

- **Audience**: an embedded engineer who already shipped a BLE app and a
  Modbus gateway, but has not owned the *firmware radio + cloud* path end to end.
- **Prerequisites**: C (and some Python), basic networking, basic embedded.

## 4. Tooling

- **Radios/boards**: ESP32 (BLE/WiFi), nRF (Zephyr BLE/Thread/Matter),
  LoRa module (TTN/Helium). Simulation via Renode/native_sim where possible.
- **Protocols**: Mosquitto (MQTT), Zephyr networking, Matter SDK.
- **Cloud**: AWS IoT Core / Azure IoT Hub / GCP IoT (free tiers).
- **Edge**: TensorFlow Lite / ONNX Runtime for the sensor-fusion/AI module.

## 5. Module breakdown (incremental)

Each module: **theory note + worked example + self-checking exercise +
deliverable**.

### I1 — IoT architecture & radio selection
- Device → edge → cloud; LPWAN vs short-range vs cellular; the connectivity decision.
- **Gap**: IoT architecture. Deliverable: a selection matrix for 3 use cases.

### I2 — BLE peripheral (GATT)
- Advertising, GATT services/characteristics, notifications; pair with the existing app.
- **Gap**: BLE. **Source**: Zephyr/nRF SDK + your shipped BLE app.
- Deliverable: a BLE sensor beacon + companion app.

### I3 — MQTT & the edge gateway
- Publish/subscribe, topics, QoS, retain; broker (Mosquitto); device → broker → dashboard.
- **Gap**: MQTT + edge. **Source**: EdgeStream-GW (Modbus → MQTT).
- Deliverable: EdgeStream-GW republished over MQTT with a live dashboard.

### I4 — Matter & Thread
- The Matter standard and Thread mesh; a Matter endpoint (light/sensor).
- **Gap**: Matter/Thread (modern smart-home). **Source**: Matter SDK + Zephyr.
- Deliverable: a Matter on/off endpoint commissioning on a Thread network.

### I5 — LPWAN (LoRaWAN / NB-IoT)
- LoRaWAN uplinks/downlinks on a public network (TTN); battery + duty-cycle math.
- **Gap**: LoRaWAN. **Source**: LoRa module + TTN docs.
- Deliverable: a battery-powered LoRaWAN telemetry node.

### I6 — Edge AI & sensor fusion
- Fuse IMU/environmental sensors; run a tiny model (TFLite/ONNX) on-device.
- **Gap**: sensor fusion + edge computing. **Source**: pytorch/edge-ai guidance.
- Deliverable: a fused sensor reading + on-device anomaly flag.

### I7 — IIoT & cloud integration
- Modbus/OPC-UA/PLC-SCADA northbound; ingest into AWS IoT Core / Azure IoT Hub.
- **Gap**: industrial automation + cloud. **Source**: EdgeStream-GW + cloud projects.
- Deliverable: gateway telemetry flowing into a cloud hub.

### I8 — Security & OTA
- Secure boot, TLS/provisioning, signed OTA with rollback.
- **Gap**: OTA + device security. **Source**: bootloader/OTA course modules.
- Deliverable: an end-to-end signed OTA on an ESP32/nRF.

## 6. Publishing plan

1. Ship I1–I3 (architecture → BLE → MQTT) as the "connected device" core.
2. Add I4–I5 (Matter, LoRaWAN) as the "modern standards" track.
3. Add I6–I8 (edge AI, IIoT, security/OTA) as the "production IoT" track.
4. Publish on **lms.helveticore.com**; tie each module to an `edge-*` repo.
